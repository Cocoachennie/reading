# Leaf · 英语外刊精读学习平台 V2.0

在原 `Cocoachennie/reading` 仓库升级，保留绿色 UI、GitHub Pages 地址和 GitHub Actions 自动更新。前端纯静态，无注册，无长期 Python 服务，不使用其他部署平台。

默认地址：https://cocoachennie.github.io/reading/

## 使用方式

1. 选择考研英语 / IELTS / TOEFL。三个列表使用各自的主题权重、语言与长度规则，独立计算适配分和排序；允许合理重叠。
2. 点击标题或卡片进入站内阅读器。开放许可正文可精读；无许可的新闻只显示元数据、允许的简介与原文链接。可通过“全部真实文章”查看未匹配条目，演示默认隐藏，公共目录已移除旧演示。
3. 选中正文中的单词、句子或段落，可多色高亮、做笔记、收藏摘录、查词、打开外部翻译或加入生词。点击正文单词也可选词；支持字号/行距/宽度、全文搜索、笔记搜索和定位。
4. “我的学习”查看收藏、阅读状态与活动时长、高亮、笔记、生词及复习历史。生词可编辑、搜索、批量 CSV 导出；填入中文释义后可进行英译中/中译英练习。
5. 定期在“备份与恢复”导出 V2 JSON。默认包含本地正文和阅读快照；文件只下载到你的设备，不上传。可取消正文，但删除浏览器数据后就无法从这种小备份恢复完整原文。旧版 V1 备份可合并导入，重复导入不重复累计时长/复习日志。

## 独立推荐与分析依据

共用的 `static/analysis.js` 在构建和浏览器运行，防止本地导入与公共文章使用两套标准。

- 考研英语：社会、经济、政策权重最高，文化、科技、教育次之；建议 450–900 词，偏 B2/C1，参考社会议题与论证型语言的编辑经验。尚未从真实历年考研题统计或校准。
- IELTS：环境、心理学、科学、教育、社会、历史等学术/半学术主题；建议 700–1400 词，偏 B2/C1。
- TOEFL：生命科学、地质、天文、考古、艺术史与历史；建议 550–1000 词，偏 B2/C1。

主题分 50 + 语言分 30 + 篇幅分 20。至少两个独立主题线索在 60 词局部窗口共同出现，再按全文线索相对密度减弱偶然提及的主题。主题门槛和完整适配最低分可调整；没有主题证据的文章不再自动混入三个考试列表。同一篇可获得三种不同分数；分数与长度区间是编辑启发式，绝不是官方标准。

有可用正文时统计英文词（内部撇号/连字符视作同一词）、正文关键词/核心词频、编辑学术词表命中频次和预计阅读分钟（180 词/分）。正文指实际展示的授权改编/用户合法文本，不拿原站未显示内容的词数充数。

至少 80 个英文词且 3 句才估计 CEFR。词汇形态复杂度 40%、句长/从属线索 35%、长度 10%、主题抽象度 15%；阈值 .33/.50/.70，映射 B1/B2/C1/C2。长难句规则为 ≥30 词，或 ≥22 词且有从属线索。这不是经过测评校准的 CEFR、句法解析或真实词汇等级模型；原形处理同样是简易规则，可人工纠正。

没有正文时：词数、CEFR、长难句、阅读时间和词汇分析不可用，只给明确标注的主题预评分，完整适配分为 null。分析失败时显示失败，不回填估计数字。考研高频词覆盖率始终为 null：没有授权真题语料、年份范围与统计分母。学术词表是代码中的小型编辑表，不是完整 AWL 或历年词频。

“验证”仅指源站获取、链接/许可和正文哈希校验，不代表新闻事实核查或历年考试采用证据。所有来源仍为推荐阅读来源，未标记任何未经核实的真题出处。

## 来源、全文权限与更新

- The Guardian Science / Environment / Business / Education / Culture、NASA News：自动读取公开 RSS 标题、链接、日期，仅元数据，不复制全文。
- The Economist：保留手动链接与合法正文导入，没有自动 API；不绕过订阅或付费墙。
- OpenStax：从官方 GitHub 的四套教材固定模块获取 8 篇叙述改编，覆盖心理/社会科学、经济、生命科学和天文。它们明确标为教材补充材料，不冒充新闻外刊。

OpenStax 当前官方仓库许可是 **CC BY-NC-SA 4.0**，不是无条件商业使用的 CC BY。脚本每次固定上游 commit、核验 LICENSE、白名单模块并保留署名、许可链接、原文版本和正文 SHA-256。仅提取叙述段落，移除图表、练习、独立引文等；发布范围与改编说明在阅读器显示。非商业、署名与相同方式共享条件适用，详见发布目录的 [开放内容声明](static/OPEN_CONTENT_NOTICES.md)。站点代码并未因此自动改用教材许可。

GitHub Actions 保持每天北京时间 **08:23 / 20:23**（UTC `23 0,12 * * *`）、推送 `main` 及手动触发。流程为：测试 → Python 采集 RSS/许可材料 → Node 共用分析器生成 JSON → 只提交公共目录 → 打包 `_site` → Pages 发布。保留最后成功时间；来源失败保留原文章和授权正文，并显示真实失败。公共档案约 500 条，优先保留许可正文。定时任务可能延迟或被 GitHub 停用，以状态和运行日志为准，不承诺准点更新。

“刷新文章”只读取最近发布的 JSON，不能让匿名静态网页拿 Token 写仓库。立即采集需在 [Actions](https://github.com/Cocoachennie/reading/actions/workflows/pages.yml) 点击 Run workflow。采集器从不读取浏览器学习存储，部署也不清空个人数据。

## 学习记录与数据保护

- 原 `leaf-personal` 的收藏、历史和本地导入保留，新增记录存于独立 `leaf-learning-v2`；公开目录缓存单独为 `leaf-catalog`。
- 阅读正文快照与字符偏移、摘录、前后文、指纹共同关联高亮。原文更新仅在唯一摘录/明确上下文时重定位；否则保留内容并提示待处理。
- 阅读状态为未读/阅读中/已完成。时长只计前台聚焦、阅读页可见且最近 90 秒有活动的会话，是活动时间估计，不是注意力测量。进度不代替用户标记完成。
- 简化 SM-2 风格复习：首次 1 天、第二次 6 天，之后依据自评分扩大（最多 365 天）；遗忘回到 1 天。用户先回忆后揭晓，自评而非机器假装理解中文同义表达。到期数在网站打开时提醒，不含后台推送。
- V2 备份覆盖收藏、进度/时长、笔记、高亮、词汇、复习和设置；合并不清空现有数据，不重复算时长/日志。写入失败尝试回退；损坏存储暂停写入并提供原始恢复文件导出。恢复文件上限 10MB，普通个人正文单篇上限 500KB。
- 浏览器配额常见为数 MB，超限有持续警告；可优先移除可再下载的公共缓存，但不会自动删个人笔记。请定期备份。浏览器/配置文件之间隔离，共用一个浏览器配置文件并不等于不同账号。
- 没有云同步。多标签同时编辑不是强一致同步，建议在一个标签页学习并定期备份；原始损坏恢复文件是排查用原件，不保证可自动修复损坏内容。

## 词典、翻译与 API 密钥

无需 API 密钥即可离线分析、记录笔记、记词和复习。小型编辑词表可填少量中文释义；未收录的音标/词性/释义留空，用户可编辑。

用户按需点击免费 dictionaryapi.dev 查询时才发送单个词，返回英文释义/音标与来源链接，失败如实显示。第三方可能限流、CORS 失败或不可访问；不是保证免费的中文词典服务。翻译按钮打开 Google Translate，最多发送选中的 1200 字符，不是站内自动翻译，按钮附近有第三方传输提示。

没有接入 AI 自动点评或付费翻译。若后续启用构建阶段翻译/AI，密钥只能使用 GitHub Actions Secrets，在构建脚本服务端调用后输出可公开的非敏感结果；禁止放进前端、URL、日志或公共 JSON。当前任何功能都不要求用户把密钥粘贴到网页。

## Pages 部署与故障排查

保留官方 Pages artifact 流程和初始化修复：deploy 具有 `contents: read`、`pages: write`、`id-token: write`；`configure-pages@v5` 使用 `enablement: true`；上传/部署名称均为 `github-pages`。

1. [Settings → Pages](https://github.com/Cocoachennie/reading/settings/pages) 的 Source 设为 GitHub Actions。
2. [工作流页面](https://github.com/Cocoachennie/reading/actions/workflows/pages.yml) → Run workflow → main。代码推送本身也会触发，不要仅重跑旧提交的失败记录。
3. 等 build/deploy 变绿，再访问 https://cocoachennie.github.io/reading/ 。若已配置自定义域名，以 Pages 设置为准。

首次创建 Pages 如仍 403，可按官方限制使用可选的仓库 secret `PAGES_ENABLEMENT_TOKEN`（fine-grained PAT 仅授权本仓库、Pages 读写）。不要放聊天或代码；初始化后可移除，后续自动回退到内置 Token。若机器人提交公共目录被 main 保护规则阻止，需仓库管理员调整策略或另设数据分支，不能强制推送绕过。

V2 第四阶段发布的 [GitHub Actions 运行 #38857236368](https://github.com/Cocoachennie/reading/actions/runs/38857236368) 已从 GitHub 运行页核实为 Success，对应提交 `b2644d0`。当前云环境直接请求 Pages 地址仍被代理 403 阻止，尚不能验收公网页面内容；后续发布以最新 Actions 结果为准。更新后可刷新页面，不要通过清除网站数据来更新，以免删除本地学习记录。

## 开发与复现

Python 3.12+、Node 24+，运行/分析不需要第三方包；仍是同一个仓库，没有长期后端或新建项目。`server.py` 保留兼容函数，生产网站不运行它。浏览器检查额外使用 Playwright/Chromium，仅测试需要。

```bash
python -m unittest discover -s tests -v
node --test tests/*.test.cjs
python scripts/update_articles.py          # 真正联网采集
python scripts/update_articles.py --offline # 只重做规则/分析，不伪造获取状态
python scripts/build_site.py
python -m http.server 8000 --directory _site
python tests/browser_v2.py                  # 纯静态 /reading/ 综合检查
```

模块：`analysis.js` 共用分析；`learning.js` 数据/锚点/复习；`reader.js` 精读；`study.js` 生词与面板；`backup.js`/`backup-ui.js` 合并恢复。`scripts/licensed_sources.py` 仅处理固定官方许可材料，`scripts/update_articles.py` 生成公共数据，工作流继续定时部署。`tests/browser_static.py` 保留为 V1 检查入口，已转接 V2 综合场景。

各阶段独立提交并测试。开发直接使用当前隔离环境的仓库，不需要另建 Git worktree。
